= Local development setup

== Prerequisites

* Docker Engine with the Compose plugin, or Docker Desktop.
* Bash for `start.sh` or PowerShell for `start.ps1`.
* Network access to pull the database and Liquibase images on the first run.

== Configure the environment

Review `dev/.env` before starting. Set the database image, exposed port, database credentials, locale, Liquibase image, and DookuG schema/service-user passwords for your environment. Keep real credentials out of shared documentation and source control.

The launchers read `dev/.env`. The Bash launcher expects `LIQUIBASE_IMAGE`; the PowerShell launcher expects `DOCKER_RUNTIME_LIQUIBASE`. Set the corresponding variable for the launcher you use. The project root `.env` is used by the separate project-image build flow, not by these development launchers.

For PostgreSQL, the launcher creates the configured local database and owner role before running the changelogs. For Oracle XE, it waits for the `XEPDB1` service and uses the configured administrator credentials for the schema bootstrap.

== Start the environment

From the repository's `dev` directory, run one of the following commands:

[source,bash]
----
./start.sh
----

[source,powershell]
----
.\start.ps1
----

Select `postgres` or `oracle` at the prompt. The launcher starts the database, then applies the schema bootstrap and DookuG master changelog. Local Liquibase files are mounted into temporary containers, so edits to changelog files are available without rebuilding a Liquibase image.

== Connect and stop

Use the connection details in xref:db_access.adoc[Local database access]. To stop and remove the database container, run `docker compose -f docker-compose.yaml down` from `dev`. To remove the database data as well, run `docker compose -f docker-compose.yaml down --volumes`; this reset is destructive.
