= Liquibase changelog conventions

== Changelog layout

The local launcher runs two master changelogs:

* `docker/dookug_db/dookug_creschema/liquibase/dookug_creschema-master.xml` bootstraps the DookuG schema and its roles. It includes the SQL changesets under `changesets/`.
* `docker/dookug_db/dookug/liquibase/dookug-master.xml` includes shared source-code changes, versioned DookuG schema/data changelogs, and shared object grants.

Version changelogs include individual change files with `relativeToChangelogFile="true"`. Follow the existing ordering and naming conventions in the relevant directory. The launcher mounts `docker/common` for the shared changelog resources used by the schema migration.

== XML changesets

Use the Liquibase XML namespace and the schema version used by the neighboring files. Current table changesets use a `changeSet` with a stable, unique ID, author, and release label. For database-specific type properties, use the shared `common/params.dtd` entity definitions where the existing changelog does so:

[source,xml]
----
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE defaultProperties SYSTEM "common/params.dtd">
<databaseChangeLog xmlns="http://www.liquibase.org/xml/ns/dbchangelog"
    xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
    xsi:schemaLocation="http://www.liquibase.org/xml/ns/dbchangelog
    http://www.liquibase.org/xml/ns/dbchangelog/dbchangelog-4.3.xsd">
    &propertiesAll;
    <changeSet id="0001" author="developer.name" labels="00.01.00">
        <comment>Describe the database change.</comment>
        <!-- Add Liquibase change types here. -->
    </changeSet>
</databaseChangeLog>
----

Check nearby changesets for the project's established SQL and XML patterns, especially for database-specific DDL and objects that require a separate follow-up changeset.

== Formatted SQL changesets

The schema bootstrap uses Liquibase formatted SQL. Use a distinct changeset ID and include a `dbms` filter when the statement applies to only one database:

[source,sql]
----
--liquibase formatted sql
--changeset developer.name:DOOKUG0001 labels:00.01.00 dbms:postgresql
--comment: Describe the PostgreSQL change

CREATE SCHEMA ${dookug_schema};

--changeset developer.name:DOOKUG0002 labels:00.01.00 dbms:oracle splitStatements:false stripComments:false
--comment: Describe the Oracle change

BEGIN
  -- Oracle-specific statements
END;
----

Use the property names and DBMS values already defined by the relevant changelog. Schema and service-user passwords are supplied by the launcher as Liquibase properties; do not hard-code credentials in new changesets.

== Migration safety

Liquibase tracks changesets after applying them. Add a new changeset and include it in the appropriate version changelog instead of modifying a changeset that has already run. Validate changes against both PostgreSQL and Oracle when the changeset targets both database engines.
