== Local development

The development launchers start a local PostgreSQL or Oracle XE database and apply the DookuG Liquibase changelogs. Liquibase runs in temporary containers and mounts changelog files from the checkout, so local changelog edits do not require rebuilding a project-specific Liquibase image.

=== Configure

Review `dev/.env` and set the database image, port, credentials, locale, Liquibase image, and DookuG schema/service-user passwords for your environment. Keep real credentials out of shared documentation.

The Bash launcher reads `LIQUIBASE_IMAGE`; the PowerShell launcher reads `DOCKER_RUNTIME_LIQUIBASE`. The project-root `.env` is used by the separate project-image build flow.

=== Start the database and apply migrations

Run the launchers from the `dev` directory:

[source,bash]
----
cd dev
./start.sh
----

[source,powershell]
----
cd dev
.\start.ps1
----

Choose `postgres` or `oracle` when prompted. The launcher starts the database if needed, waits for it to be ready, then runs two Liquibase updates for the `dookug` schema:

. `dookug_creschema-master.xml` creates the schema, users, roles, and privileges.
. `dookug-master.xml` applies the DookuG schema and data changelogs.

Liquibase tracks applied changesets. Add a new changeset for each migration; do not modify a changeset that has already been applied.

=== Manage database containers

Run these commands from `dev` to start or stop only a database container:

[source,bash]
----
docker compose -f docker-compose.yaml up -d postgres
# Use oracle instead of postgres to start Oracle XE.
docker compose -f docker-compose.yaml up -d oracle

docker compose -f docker-compose.yaml down
----

To remove the local database data as well as the container, run `docker compose -f docker-compose.yaml down --volumes` from `dev`. This reset permanently deletes local database data.

== Development

=== Generating license headers

Use https://pre-commit.com/[pre-commit] to generate license headers in new AsciiDoc, shell, and YAML files. Install it once; the hook will then run automatically on each commit.

`.pre-commit-config.yaml` configures the hooks and the file types to check. `.sourceheaders.toml` contains the license header templates and per-file-type settings.

Before setting up pre-commit, install https://www.python.org/[Python 3] and https://pypi.org/project/pip/[pip]. Then run:

[source,bash]
----
pip install pre-commit
pre-commit install
----

After setup, `pre-commit` runs automatically on `git commit`.
