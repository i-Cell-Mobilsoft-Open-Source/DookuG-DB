= Installation, Release, Deployment

== Build the Liquibase images

From the project root, build both images:

[source,console]
----
./build.sh
----

The build produces separate images for creating the project schema and users, and for applying the DookuG schema changelog. Their names and tags are configured in the project root `.env` file.

== Install or update a database

The deployment uses two Liquibase runs, in order:

. Configure `JDBC_URL` and credentials in `docker/dookug_db/dookug_creschema/.env` for the target PostgreSQL or Oracle database. This run creates the project schema, service user, and related permissions. Run `./run.sh` from that directory.
. Configure `JDBC_URL`, `DOOKUG_SCHEMA`, and `DOOKUG_SCHEMA_PASSW` in `docker/dookug_db/dookug/.env`. Run `./run.sh` from that directory to apply the DookuG changelog.

The checked-in installer `.env` files contain sample settings. Replace sample credentials and connection details before use. For an existing host database, point both files at that database; schema creation and schema migration remain separate runs.

== Local development database

The development scripts start a local database, create the PostgreSQL project database when needed, and run both Liquibase changelogs. They support PostgreSQL and Oracle XE; EDB is not an option in these scripts.

On Linux or macOS, run from the `dev` directory:

[source,console]
----
./start.sh
----

On Windows, run `start.ps1` from the `dev` directory. The script prompts for `postgres` or `oracle` and defaults to PostgreSQL. Database images, ports, and local credentials are configured in `dev/.env`.
