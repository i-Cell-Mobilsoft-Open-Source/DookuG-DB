= Local development and Compose commands

== Run the local database and migrations

The development launchers start PostgreSQL or Oracle XE, then run Liquibase against the selected database. Liquibase runs in temporary containers and mounts the changelog files from the local checkout; no project-specific Liquibase image build is needed for local changes.

Run the launcher from the `dev` directory so the Bash launcher resolves the changelog mount paths correctly:

[source,bash]
----
cd dev
./start.sh
----

On Windows, run the PowerShell launcher from `dev`:

[source,powershell]
----
cd dev
.\start.ps1
----

Choose `postgres` or `oracle` when prompted. PostgreSQL is the default. The launcher starts the database container if necessary, waits for it to be ready, and applies two Liquibase updates:

. The `dookug_creschema-master.xml` changelog creates the schema, users, roles, and privileges.
. The `dookug-master.xml` changelog applies the DookuG schema and data changes.

Liquibase records applied changesets in the database. Add a new changeset for a new migration; do not edit a changeset that has already been applied.

== Compose commands

Run these commands from `dev` when you need to manage only the database container:

[source,bash]
----
docker compose -f docker-compose.yaml up -d postgres
# Or start Oracle XE:
docker compose -f docker-compose.yaml up -d oracle
----

Stop and remove the database container:

[source,bash]
----
docker compose -f docker-compose.yaml down
----

To reset the local database, remove its Docker volumes as well. This permanently deletes the local database data:

[source,bash]
----
docker compose -f docker-compose.yaml down --volumes
----

The local settings are read from `dev/.env`. The Bash launcher reads `LIQUIBASE_IMAGE`; the PowerShell launcher reads `DOCKER_RUNTIME_LIQUIBASE`. Both settings identify the Liquibase runtime image. The separate project image-build configuration at the repository root is not used by these launchers.
